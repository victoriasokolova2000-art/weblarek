# Проектная работа "Веб-ларек"

Стек: HTML, SCSS, TS, Vite

Структура проекта:
- src/ — исходные файлы проекта
- src/components/ — папка с JS компонентами
- src/components/base/ — папка с базовым кодом

Важные файлы:
- index.html — HTML-файл главной страницы
- src/types/index.ts — файл с типами
- src/main.ts — точка входа приложения
- src/scss/styles.scss — корневой файл стилей
- src/utils/constants.ts — файл с константами
- src/utils/utils.ts — файл с утилитами

# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные
В этом разделе описаны интерфейсы, определяющие структуру данных, которые используются в приложении. Все они находятся в файле `src/types/index.ts`.

#### Интерфейс IProduct 
Описывает структуру товара, который хранится и отображается в приложении. 
`interface IProduct { id: string, title: string, image: string, category: string, price: number | null, description: string}` 

#### Интерфейс CartItem
Интерфейс наследует данные о продукте, но учитывает количество товара.
`interface CartItem extends IProduct {quentity: number}`

#### Интерфейс IBuyer 
Описывает структуру данных покупателя, которые собираются при оформлении заказа. 
`interface IBuyer { payment: TPayment | ''; email: string; phone: string; address: string; }`

Пустая строка в `payment` — это состояние «покупатель ещё не выбрал оплату». Такой вариант позволяет модели всегда хранить все четыре поля и не использовать `undefined`, благодаря чему сохранение одного поля не затрагивает остальные.

`type TPayment = 'card' | 'cash'` - хранит допустимые способы оплаты, гарантирует, что в поле payment не попадут некорректные значения

#### Тип TBuyerErrors
Описывает результат валидации данных покупателя. Ключ присутствует в объекте только для того поля, которое не прошло проверку, а его значение — текст ошибки. Пустой объект означает, что все данные корректны.
`type TBuyerErrors = Partial<Record<keyof IBuyer, string>>;`

### Модели данных

Классы этого слоя отвечают только за хранение данных и операции над ними. Они не работают с DOM, не выполняют запросы к серверу и не зависят от других классов приложения, поэтому могут использоваться самостоятельно.

#### Класс CatalogModel
Отвечает за хранение каталога товаров, доступных для покупки, и товара, выбранного пользователем для подробного отображения.

Конструктор не принимает параметров.

Поля класса:
`products: IProduct[]` — массив всех товаров каталога. По умолчанию пустой массив.
`selectedProduct: IProduct | null` — товар, выбранный для подробного отображения. По умолчанию `null`, так как при запуске приложения ни один товар не выбран.

Методы класса:
`saveProducts(products: IProduct[]): void` — сохраняет в модели переданный массив товаров.
`getProducts(): IProduct[]` — возвращает массив всех товаров каталога.
`getProductById(id: string): IProduct | undefined` — возвращает товар с переданным идентификатором или `undefined`, если товар не найден.
`saveSelectedProduct(product: IProduct | null): void` — сохраняет товар для подробного отображения. Передача `null` сбрасывает выбор.
`getSelectedProduct(): IProduct | null` — возвращает товар, выбранный для подробного отображения.

#### Класс CartModel
Отвечает за хранение товаров, которые покупатель выбрал для покупки.

Конструктор не принимает параметров.

Поля класса:
`items: IProduct[]` — массив товаров, добавленных в корзину. По умолчанию пустой массив.

Методы класса:
`getItems(): IProduct[]` — возвращает массив товаров, находящихся в корзине.
`addItem(item: IProduct): void` — добавляет переданный товар в корзину.
`removeItem(item: IProduct): void` — удаляет переданный товар из корзины, сравнивая товары по `id`.
`clear(): void` — полностью очищает корзину.
`getTotalPrice(): number` — возвращает суммарную стоимость товаров в корзине. Товары с ценой `null` в сумму не входят.
`getItemsCount(): number` — возвращает количество товаров в корзине.
`hasItem(id: string): boolean` — проверяет наличие в корзине товара с переданным идентификатором.

#### Класс BuyerModel
Отвечает за хранение данных покупателя и проверку их заполненности.

Конструктор не принимает параметров.

Поля класса:
`payment: TPayment | ''` — выбранный способ оплаты. По умолчанию пустая строка.
`email: string` — емэйл покупателя. По умолчанию пустая строка.
`phone: string` — телефон покупателя. По умолчанию пустая строка.
`address: string` — адрес доставки. По умолчанию пустая строка.

Все поля инициализированы пустыми значениями, поэтому модель всегда хранит полный набор данных покупателя.

Методы класса:
`setData(data: Partial<IBuyer>): void` — сохраняет данные покупателя. Принимает объект с любым набором полей, поэтому можно сохранить, например, только адрес или только телефон. Поля, отсутствующие в переданном объекте, сохраняют ранее записанные значения.
`getData(): IBuyer` — возвращает объект со всеми данными покупателя.
`clearData(): void` — очищает данные покупателя, возвращая все поля к пустым значениям.
`validate(): TBuyerErrors` — проверяет заполненность данных и возвращает объект с текстами ошибок. Поле считается валидным, если оно не пустое. Ключ поля, прошедшего проверку, в объекте отсутствует; пустой объект означает, что все данные валидны.

### Слой коммуникации

Классы этого слоя отвечают за обмен данными с сервером.

#### Класс ApiService
Отвечает за получение данных с сервера и отправку данных на сервер. Класс использует композицию: в конструктор передаётся объект, соответствующий интерфейсу `IApi`, и класс делегирует ему выполнение запросов через методы `get` и `post`. Благодаря этому `ApiService` не зависит от конкретной реализации HTTP-клиента, и её можно заменить, например, при тестировании.

Конструктор:
`constructor(api: IApi)` — принимает объект, соответствующий интерфейсу `IApi`, и сохраняет его для выполнения запросов.

Поля класса:
`api: IApi` — объект, которому делегируются запросы к серверу.

Методы класса:
`getProducts(): Promise<IProductsResponse>` — выполняет GET-запрос на эндпоинт `/product/` и возвращает промис с объектом, в котором находится массив товаров каталога.
`createOrder(order: IOrderRequest): Promise<IOrderResponse>` — выполняет POST-запрос на эндпоинт `/order/`, передавая полученные в параметре данные заказа, и возвращает промис с объектом, подтверждающим покупку на определённую сумму.

Базовый адрес сервера не задаётся в классе напрямую. Он читается из переменной окружения `VITE_API_ORIGIN` в файле `src/utils/constants.ts` (константа `API_URL`), а готовый клиент создаётся в файле `src/components/client.ts`. Поэтому методам `ApiService` достаточно передавать только эндпоинт.
